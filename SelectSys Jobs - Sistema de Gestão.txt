 SelectSys Jobs - Sistema de Gestão de Processo Dekassegui (Brasil → Japão)

    Visão Geral do Produto

    O SelectSys Jobs é um SaaS multi-tenant especializado na gestão completa do processo de exportação de mão de
    obra do Brasil para o Japão (dekassegui). Diferente de um ATS genérico, nosso sistema foi construido
    especificamente para atender às exigências únicas deste fluxo, incluindo:

    - Pipeline de 11 etapas com 17 estados de processo distintos
    - Integração com sistemas japoneses (como Garoon)
    - Geração de documentos no layout exato exigido pelos parceiros japoneses
    - Gestão de requisitos específicos (descendência japonesa, limite de idade, vistos, COE)
    - Suporte a múltiplas agências indicadoras dentro da mesma organização

    Como o Sistema Funciona

    1. Pipeline de Processo Dekassegui

    O sistema gerencia todo o fluxo desde a candidatura inicial até a admissão no Japão, seguindo exatamente as 11
    etapas definidas pelo cliente:


    Candidatura → Triagem → Entrevista → Garoon → Envio currículo ao Japão →
    Seleção pela empresa japonesa → Aprovação/Oferta → COE → Visto → Viagem → Admissão


    Cada candidatura passa por 17 estados possíveis, incluindo terminais como reprovado, desistente e inativo.
    As transições entre estados são configuráveis via tabela (não hardcodeadas), permitindo que o cliente ajuste o
    funil sem necessidade de deploy técnico.

    2. Formulário Inteligente e Versionado

    Ao invés de um formulário fixo, o sistema utiliza um motor de formulários dirigidos por schema que:

    - Substitui a planilha Excel atual mantendo o layout 100% idêntico na exportação (bloqueador crítico para
    adoção pelo parceiro japonês)
    - Permite rascunho e autosave para o formulário extenso (~130 campos)
    - É totalmente configurável - o cliente pode modificar campos, validações e layout sem intervenção técnica
    - Suporta versionamento de formulário (como o "Jun/2024" no rodapé da planilha atual)
    - É mobile-first (80% dos candidatos preenchem via celular)

    Estrutura técnica do formulário:
    - Campos normalizados (~35): data de nascimento, sexo, geração, província, nível, status, altura/peso/pé
    (indexáveis para busca e relatórios)
    - Campos dinâmicos (~95): perguntas da enquete armazenadas em JSONB versionado por schema, permitindo que cada
    agência tenha seu próprio conjunto de perguntas
    - Mapeamento de exportação que liga cada campo do sistema à célula exata do .xls original (ex: `"nome_completo":
    "Ficha cadastral!G6"`)

    3. Motor de Regras de Triagem (Explicável e Auditável)

    A triagem automática não é mais uma série de ifs escondidos no código, mas sim **regras como dados
    versionados**:

    jsonc
    {
      "ruleset_version": 3,
      "rules": [
        {
          "id": "idade_maxima",
          "priority": 10,
          "when": { "all": [ { "fact": "idade", "op": ">=", "value": 55 } ] },
          "unless": { "any": [ { "fact": "trabalhou_mesma_empresa", "op": "==", "value": true } ] },
          "then": {
            "outcome": "reprovar",
            "reason_code": "IDADE_ACIMA_LIMITE",
            "message": { "pt-BR": "Idade acima de 55 anos sem histórico na mesma empresa." }
          }
        },
        {
          "id": "descendencia_obrigatoria",
          "priority": 20,
          "when": { "all": [ { "fact": "geracao", "op": "==", "value": "nao_descendente" } ] },
          "then": { "outcome": "encerrar_fluxo", "reason_code": "SEM_DESCENDENCIA" }
        }
      ]
    }


    Benefícios desta abordagem:
    - Explicabilidade: O sistema grava exatamente quais regras foram disparadas, com snapshot dos dados de
    entrada e versão da regra, permitindo responder claramente "por que esse candidato foi reprovado?"
    - Conformidade LGPD Art. 20: O candidato tem direito à revisão de decisões automatizadas - nosso sistema
    fornece toda a trilha necessária
    - Flexibilidade: O cliente pode modificar regras (ex: mudar o limite de idade de 55 para 60) via interface
    administrativa, sem necessidade de deploy
    - Reprocessamento seguro: Ao mudar uma regra, é possível rerodar todo o banco e comparar resultados antes de
    aplicar a mudança em produção

    4. Sistema de Matching e Compatibilidade (Serviço Premium)

    O matching é totalmente determinístico em dois estágios:

    Estágio 1 - Restrições rígidas (elimina imediatamente):
    - Descendência japonesa obrigatória
    - Idade < 55 (exceto se trabalhou na mesma empresa)
    - Visto válido
    - Compatibilidade de turno e disponibilidade de horas extras
    - Restrições de saúde incompatíveis com o posto (ex: daltonismo × inspeção visual de componentes eletrônicos)

    Estágio 2 - Score ponderado 0-100 (configurável por vaga):
    | Critério                                                      | Peso Sugerido |
    |---------------------------------------------------------------|---------------|
    | Experiência no mesmo setor (eletrônica/autopeças/alimentício) | 25            |
    | Experiência prévia no Japão / mesma empreiteira               | 20            |
    | Compatibilidade de turno e horas extras                       | 15            |
    | Preferência de província × província da vaga                  | 10            |
    | Nível de japonês                                              | 10            |
    | Aptidão física para o posto (em pé, peso, ergonomia)          | 10            |
    | Disponibilidade de embarque × prazo da vaga                   | 10            |

    Saída sempre explicável:

    Compatibilidade 78/100 - Fábrica Aichi / Autopeças / turno alternado
         3 anos em autopeças (Toyota Boshoku)         +25
         Aceita turno alternado                        +15
         Já trabalhou no Japão (Aichi)                 +20
         Nível de japonês: básico (vaga pede intermediário)   0 / 10
          Embarque pretendido em 6 meses; vaga fecha em 60 días  +4 / 10

      Para chegar a 90+: comprovar N4 e antecipar disponibilidade.


    Este é exatamente o produto premium que o cliente pode oferecer: o candidato não paga por um número arbitrário,
    mas por um plano de ação claro que mostra exatamente o que precisa fazer para aumentar suas chances.

    5. Integrações e Automações

    - Garoon: Integração via REST API (se cloud) ou adaptação para on-premise, enviando apenas candidatos
    aprovados na entrevista
    - WhatsApp: Mensagens automáticas via Meta WhatsApp Cloud API com controle de não-respondidos e histórico
    completo
    - Documentos: Estado máquina para cada documento (não_solicitado → solicitado → enviado → conferido)
    - Dashboard e Lembretes: Trabalhos agendados para entrevistas, prazos de COE, visto, viagem e admissão
    - Exportação: Geração do .xls usando ExcelJS preenchendo o template original (não gerando do zero),
    garantindo layout idêntico

    6. Arquitetura Multi-tenant desde o Início

    Embora o primeiro cliente seja a parceira japonesa, o sistema foi projetado para atender às ~30 empreiteiras do
    mesmo mercado desde o primeiro dia:

    - Isolamento rígido entre organizações usando organization_id em todas as tabelas + RLS (Row Level Security) do
    PostgreSQL
    - Um cliente adicional não requer novo deploy - apenas configuração via interface
    - Margem de lucro aumenta significativamente com cada novo cliente (mesma infraestrutura suporta 8-10
    organizações do porte inicial)
    - Evita o retrabalho extremamente caro de retrofit de multi-tenancy posteriormente

    7. Segurança e Conformidade LGPD

    Dado que o Bloco B do formulário contém dados pessoais sensíveis de saúde (depressão, medicação, alergias, etc.),
    implementamos:

    - Tabela separada para dados de saúde com criptografia em nível de coluna (AES-256-GCM)
    - Log de acesso completo a cada leitura desses dados (quando, quem, qual candidato, qual campo)
    - Consentimento específico e versionado com texto explícito, timestamp e IP armazenados
    - Política de retenção automática (sugestão: 24 meses após último contato)
    - RLS restringindo acesso apenas a papéis entrevistador e acima

    8. Onde a IA Entra (e Nunca Entra)

    A IA (Claude) é utilizada exclusivamente em tarefas periféricas, nunca na tomada de decisões de
    aprovação/reprovação:

    Onde a IA É utilizada:
    - Tradução PT   JA para staff japonês ler perfis em 30 segundos ao invés de 10 minutos
    - Extração estruturada de histórico em texto livre ("trabalhei na Nissin em Shizuoka de 2019 a 2021")
    - OCR de documentos (passaporte, RG, carteira de residente)
    - Detecção de inconsistências (ex: "declarou nunca ter ido ao Japão, mas informou Reentry Permit")
    - Geração de one-pager de apresentação do candidato para empresa japonesa

    Onde a IA NUNCA é utilizada:
    - Aprovação ou reprovação de candidatos
    - Cálculo de score de compatibilidade
    - Qualquer decisão que afete o fluxo do processo

    Isso garante conformidade com LGPD Art. 20 e evita vieses algorítmicos em decisões críticas.

    Por Que Funciona Dessa Forma

    Decisões Arquiteturais Fundamentais

    1. Configuração > Código
       Todas as regras de negócio (formulário, triagem, matching) são dados, não código. Isso permite que o cliente
    mude critérios de idade, adicione campos ao formulário ou ajuste pesos de matching sem precisar de nós para fazer
    um deploy. Resolve o problema de regras que "mudam constantemente" mencionado na análise.

    2. Decisões Auditáveis
       Toda triagem e score grava: snapshot dos dados de entrada, versão da regra usada, regras disparadas e
    resultado. Isso:
       - Atende diretamente à LGPD Art. 20 (direito à revisão)
       - Elimina discussões subjetivas com candidatos ("por que fui rejeitado?")
       - Permite reprocessamento seguro quando regras mudam

    3. Monólito Modular (não Microserviços)
       Para um cliente inicial, microserviços seriam over-engineering que:
       - Aumentariam complexidade operacional desnecessariamente
       - Criariam pontos de falha adicionais
       - Tornariam desenvolvimento mais lento
       Nossa abordagem de módulos com fronteiras limpas dentro de um único deploy oferece o melhor equilíbrio entre
    escalabilidade inicial e simplicidade operacional.

    4. IA na Periferia, Nunca no Veredito
       Isso é não apenas uma escolha técnica, mas um requisito de conformidade e confiança:
       - LGPD Art. 20 exige que decisões automatizadas sejam revisíveis
       - Clientes japoneses e brasileiros desconfiam de "caixas pretas" em decisões de contratação
       - Mantém a transparência necessária para auditorias e relacionamento com parceiros

    Valor de Negócio para o Cliente

    1. Elimina o Gargalo da Planilha
       Substitui o processo manual eerror-prone de preenchimento da planilha por um formulário web com validação em
    tempo real, rascunho e autosave, reduzindo significativamente o tempo de processamento por candidatura.

    2. Garantia de Compatibilidade com Parceiros Japoneses
       A exportação 100% idêntita ao .xls atual remove o maior bloqueador para adoção - o parceiro japonês a jusante
    continua recebendo exatamente o formato que espera, sem necessidade de adaptação do loro lado.

    3. Redução de Trabalho Manual e Erros
       - Triagem automática substitui revisão manual básica
       - Lembretes automatizados reduzem perdas de candidatos por esquecimento de prazos
       - Estado máquina de documentos elimina perda de acompanhamento de solicitações

    4. Diferencial de Mercado Claro
       Enquanto um ATS genérico compete diretamente com soluções estabelecidas (Gupy, Solides), nosso sistema fala a
    linguagem específica do dekassegui:
       - Entende COE, Koseki, Reentry
       - Gerencia requisitos de província e empreiteira específica
       - Trata questões de descendência japonesa como critério legítimo de visto
       Isso cria um monopólio de fato no nicho específico, sem concorrentes diretos.

    5. Escalabilidade Previsível
       A arquitetura foi dimensionada para crescer com o cliente:
       - Primeiro cliente: ~R$104/mês (variável) + R$61 fixo = R$165/mês total
       - Margem inicial de ~39% em plano de R$100
       - Cada cliente adicional aumenta a margem para perto de 100% (mesma infraestrutura suporta múltiplas
    organizações)

    6. Base para Expansão de Mercado
       Depois de estabelecido com o primeiro cliente, o mesmo sistema pode ser vendido para outras empreiteiras do
    mercado dekassegui com apenas ajustes de configuração (formulário, regras de triagem, pesos de matching), criando
    receita recorrente com custo marginal quase zero.

    Próximos Passos para Implementação

    1. Configuração Inicial

       - Configurar vagas iniciais com seus respectivos critérios

    2. Treinamento e Adoção
       - Treinar equipe interna no uso do painel administrativo

    3. Integrações
       - Validar se Garoon é cloud ou on-premise para definir abordagem de integração
       - Configurar WhatsApp Business API com número oficial da empresa
       - Alinhar com equipe japonesa sobre formato esperado de currículos enviados

    4. Go-live e Otimização
       - Período paralelo de uso da planilha e do sistema para validação
       - Coleta de feedback para ajustes finos no formulário e fluxo
       - Otimização de custos variáveis baseado no volume real de uso
